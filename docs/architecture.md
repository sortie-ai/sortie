# Sortie Architecture

This document is derived from the [Symphony Service Specification](https://github.com/openai/symphony/blob/main/SPEC.md). Sortie is a concrete Go implementation, not a language-agnostic specification. Key adaptations from Symphony include: agent-agnostic design with Claude Code as the first supported runtime, tracker-agnostic design with Jira as the first supported tracker, SQLite-backed persistence for retry queues and run history, adapter-based extensibility for both agent runtimes and issue trackers, and orchestrator-level handoff transitions that break the continuation retry loop without relying on agent behavior.

This page is an index. The specification lives in one file per section under [`architecture/`](architecture/); open only the section your task touches. When the index summary and a section file disagree, the section file wins: the index is a map, not a second source of truth. Accepted architecture decisions are recorded in [`decisions/`](decisions/).

## System at a glance

Sortie is a long-running automation service. It polls an issue tracker on a fixed cadence, creates an isolated per-issue workspace, and runs a coding-agent session for each eligible issue inside that workspace. An orchestrator owns the poll tick and the authoritative runtime state for dispatch, retries, and reconciliation, backed by durable storage so it survives process restarts. Runtime policy lives in a repository-owned `WORKFLOW.md` that supplies both the typed configuration and the agent prompt. Issue trackers, coding-agent runtimes, CI status providers, and SCM platforms are reached through adapter interfaces, so a new integration is an additive package behind an existing contract rather than a change to core orchestration. Sortie is primarily a scheduler and tracker reader: free-form ticket mutation belongs to the agent through its own tools, while the orchestrator writes tracker state at exactly three configured points, each one reporting an event it observed. A successful run may end at a workflow-defined handoff state rather than `Done`.
